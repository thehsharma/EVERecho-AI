# The pitch-and-manual document

`docs/EverEcho-v0.1-Pitch-and-Manual.pdf` — 57 pages, A4, with a linked table of
contents and PDF bookmarks. It is the whole project in one document: the pitch,
the manual, and the technical record including the honest production-readiness
verdict.

## What is in it

| Part | Sections | What it covers |
|---|---|---|
| I — The pitch | 1–8 | The problem, what EverEcho is and is not, why the boundary is the product, the six roles, the consent architecture, provenance, and the measured evidence |
| II — The manual | 9–13 | Getting it running, the demonstration archive, all 16 screens with commentary, the command reference, and troubleshooting |
| III — Under the hood | 14–20 | Architecture, the data model, security and privacy engineering, what was measured, the readiness verdict, the next five actions, and a repository map |

Every figure is a screenshot of the application running locally against a real
PostgreSQL 16 database. There are no mockups in it, and no figure was projected
or estimated.

## Rebuilding it

The document is print-styled HTML rendered to PDF by headless Chromium.

```bash
# 1. Capture the screenshots (needs the stack running and seeded)
#    into a directory of PNGs named 01-landing.png … 16-tablet-overview.png
# 2. Point SHOTS in src/assemble.py at that directory, then:
python3 src/assemble.py          # inlines the PNGs as data URIs -> document.html
node src/render.mjs              # document.html -> the PDF
```

`src/parts/*.html` are concatenated in filename order, so section order is the
filename order. `src/style.css` holds the A4 print stylesheet: `@page` rules,
the cover, part dividers, callouts, tables, figures and badges.

The screenshots themselves are not committed — they are regenerated by running
the application, which is the only way this document stays honest about showing
software that actually runs.
