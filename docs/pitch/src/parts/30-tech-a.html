Decisions worth defending

Packages are consumed as TypeScript source

Each package exports "./src/index.ts" directly. There is no build step, no dist directory, and no chance of a stale compiled artifact disagreeing with its source. tsc --noEmit typechecks the whole graph at once, and tsx runs it. Decision D‑002.

Hand-written SQL, not an ORM

Eight numbered migrations, each checksummed. Row-level security policies, FORCE ROW LEVEL SECURITY, generated tsvector columns, an append-only audit trigger and a PL/pgSQL cosine-distance function are all things an ORM either cannot express or expresses badly. The queries that enforce consent obligations are the most security-critical code in the product; they should be readable as SQL. Decision D‑003.

The job queue lives in PostgreSQL, not Redis

SELECT … FOR UPDATE SKIP LOCKED. This matters for a specific reason: enqueueing a job is transactional with the domain change that caused it. A memory cannot be created without its embedding job being queued, and a rolled-back transaction cannot leave an orphaned job behind that processes data the rollback was meant to prevent. Redis remains, for cache and rate limiting, where losing data is acceptable. Decision D‑004.

Embeddings as real[], with pgvector optional

The portable path works on any PostgreSQL 16 with no extensions, using a PL/pgSQL cosine-distance function. Where pgvector is present, an optional migration adds a synced column and an HNSW index, and a db_capability table records the detection so the query planner path is chosen at runtime rather than assumed. The product does not require an extension its host may not offer. Decision D‑006.

scrypt, from the Node standard library

Password hashing uses Node's built-in scrypt rather than argon2. The reasoning is deployment rather than cryptography: argon2 is a native dependency, and a native dependency that fails to build is an authentication system that does not start. scrypt is memory-hard, standard-library, and always present. Decision D‑005.

OpenAPI generated from the validating schemas

docs/openapi.json is produced by z.toJSONSchema() over the same Zod schemas that validate requests and responses at runtime. The document cannot describe an endpoint that does not exist, or omit a field the implementation requires, because there is only one definition.
