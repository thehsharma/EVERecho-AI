5  The six people who use it

Authority is not a ladder. The buyer paid for the archive and has less authority over its contents than anyone. No ordering between these roles is implied anywhere in the codebase.

RoleWhat they can doWhat they can never do
Storyteller
The living person whose memories these are		 Everything. Record, review, approve, edit, reject, set and change consent, see drafts, revoke access, delete the archive. — final authority throughout
Buyer
Set it up, pays for it		 Manage membership and billing. Invite people. See that the archive exists and is healthy. Read a single memory, unless separately granted as family. Consent on the storyteller's behalf. Approve anything.
Family
A daughter, a grandson		 Read approved memories within their grant. Browse the timeline. Ask cited questions. Request an export if consent permits it. See drafts or rejected material. See anything above the sensitivity ceiling on their grant. Edit anything.
Contributor
A sibling who was also there		 Everything family can, plus proposing corrections and additional context. Silently overwrite anything. A proposal is a record awaiting the storyteller, never an edit.
Steward
Named for continuity		 Narrowly delegated continuity tasks under a recorded succession directive. Act as executor or owner. Be activated by a timer, an absence, or any automatic signal.
Support admin
Internal		 Operational metadata: job states, error codes, storage counts. Break-glass access that is purpose-limited, time-bound and audited. Read memory content. The scope is admin_scope_metadata_only; content actions deny before any query is built.
One decision point

Every one of these boundaries is expressed in a single pure function — authorize(actor, action, resource, subject, context) — that performs no I/O and returns either ALLOW with obligations or DENY with a reason code. There is no second place in the codebase where a permission is decided, and no route can reach data without passing through it.

6  Consent as an architecture, not a checkbox

Consent here is a versioned, canonically serialised, hashed policy document. It is compiled, not read. It has a ceiling and it has grants, and they are independent.

Five modes; the fifth is refused

ModeWhat it permitsStatus
preserveEncrypted archive only. No processing of any kind — no transcription, no indexing, nothing derived.available
organiseTranscription, OCR, indexing, and reviewed structure.available
exploreSearch, timeline and retrieval across the archive.available
composeSource-grounded biography and third-person cited answers.available
performSynthetic voice, avatar, persona.prohibited

perform exists in the type system precisely so that every switch in the codebase must acknowledge and refuse it. Deleting the value would let a future branch silently forget to handle it; keeping it means the compiler enforces the refusal. The policy compiler rejects any document that requests it, with a named reason rather than a generic validation error.

The mode is a ceiling, not a bundle

Selecting compose does not grant transcription, embedding, export and generation. Each of nine processing activities — storage, transcription, ocr, embedding, generation, provider_processing, provider_retention, export, contribution — is granted independently. The mode sets the highest thing that may be granted; the grants say what actually is. An early version of this build collapsed the two, and the consent tests caught it as a bug.

consent document (JSON) │ ├─▶ prohibitedShapeIssues() ── refuses voice/likeness/training ─▶ named refusal ├─▶ zod schema parse ── shape and enum validity ├─▶ canonicalise() ── stable key order, stable encoding ├─▶ sha256(canonical) ── the policy hash, stored with the record └─▶ compileConsentPolicy() ── the object authorize() actually reads

What consent controls, precisely

Ceilings and gates

  • Mode ceiling
  • Activity grants (nine, independent)
  • Provider processing and retention, gated separately from local processing
  • Data categories, including the special ones: health, financial, religious, political, sexual orientation, biometric

Scope and time

  • Excluded sources — "not that recording, ever"
  • Embargoes — "not until 2035"
  • Restricted topics — "never about my first marriage"
  • Sensitivity ceiling per recipient grant
  • Recipient grants with expiry windows
Revocation is not eventual

When consent is narrowed, the change takes effect on the next authorisation check — which is every request. Background jobs already queued re-check consent inside their own transaction before writing anything, so a job that was legitimate when enqueued and is not legitimate when it runs will not produce a row. This was a deliberate decision (D‑009) with a test that fails if a handler skips the check.

Teach-back: consent you can demonstrate understanding of

Before a consent policy is recorded, the storyteller is asked to answer, in their own words, what they have just agreed to. The response is stored alongside the policy hash. This is not a quiz that gates the flow — it is evidence, kept with the record, that the consent was informed. Legal review of the wording is item 1 on the blocking list in Part III.
