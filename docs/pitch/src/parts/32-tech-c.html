Why "no mocks" is the load-bearing phrase

The 48 integration tests run against a real database. This is slower and more awkward than mocking the data layer, and it is the only way to test the things that actually matter here: row-level security is a property of PostgreSQL, not of application code, and a mocked database will happily confirm an isolation guarantee that does not exist. The same applies to the append-only audit trigger, the FOR UPDATE SKIP LOCKED queue semantics, the generated tsvector columns and the consent obligations compiled into WHERE clauses.

How the evaluation suite avoids grading its own homework

The 32 gold-set cases check citations against the database rather than against the response. An answer that cites a memory identifier it invented fails, because the harness looks the identifier up. The suite exits non-zero on any missed target, so a regression in grounding blocks the build rather than producing a slightly worse number in a report nobody reads.

Bugs the tests actually caught

Listed because a test suite that never caught anything is decoration:

  • Consent (4 real bugs): reason codes returned in the wrong order so the buyer case reported a misleading denial; a mode‑to‑activity mapping that collapsed nine independent grants into a bundle; two roles missing their export actions, which put the decision in the role table instead of in consent; and correction.propose skipping the recipient-grant lookup entirely.
  • Retrieval: websearch_to_tsquery's AND semantics silently returning nothing for multi-word questions; non-deterministic ordering on ranking ties; no irregular-verb stemming, so "move" and "moved" did not converge.
  • Safety: injection questions receiving cited answers because the check ran after retrieval rather than before it.
  • Rate limiting: the limiter registered before session resolution, so every request was keyed by IP address — which meant all server-rendered traffic shared a single bucket and would have locked every user out under real load.
  • Audit: denial records written inside the transaction that the denial rolled back, so no refusal was ever recorded.
  • Seeding: consent rows written outside an archive scope — correctly rejected by RLS, which is the isolation working as designed.
The rate-limiting bug is the one to remember

It passed every test. It broke nothing in development. It would have taken the product down on its first day of real traffic, and it was found by reading the hook registration order while looking for something else. Not every class of defect is reachable by a test suite.

Known gaps, stated plainly

  • No password reset. A user who forgets their password has no route back.
  • No MFA enrolment, though the columns and the adapter boundary exist.
  • No notification scheduling. Email is sent inline; there is no digest or reminder system — deliberately, given how easily reminders become nudges.
  • No admin UI for incidents beyond a read-only list.
  • Contributor proposals are recorded but there is no review queue for them.
  • OpenTelemetry is configured but not instrumented.
  • No backfill for changing the embedding model. Changing EMBEDDINGS_DIM invalidates stored vectors and needs a re-embed script that does not exist.
  • The local speech adapter cannot recognise speech. It transcribes text captured alongside a recording and reports honestly otherwise. Real audio needs a provider.
  • Interview audio capture has no automated test. MediaRecorder and browser speech recognition are exercised by hand only.
  • The ERD is a text diagram, not a rendered image.
