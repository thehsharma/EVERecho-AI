9  Getting it running

Node 22+, pnpm 10+ and PostgreSQL 16. Nothing else, and no paid API keys — every provider has a working local adapter.

First run, from a clean checkout

git clone <this repository> && cd EVERecho-AI
pnpm install
cp .env.example .env          # the defaults work as they are

createdb everecho             # or: psql -c 'CREATE DATABASE everecho'

pnpm db:migrate               # applies the eight numbered migrations
pnpm db:seed                  # builds a synthetic demonstration archive

Then start the three processes, each in its own terminal:

pnpm dev:api                  # http://localhost:4000
pnpm dev:worker               # background processing
pnpm dev:web                  # http://localhost:3000

Open http://localhost:3000/demo and sign in as any of the demonstration accounts. There is a shortcut: pnpm setup runs install, migrate and seed in one step.

Why there are no API keys

Every external provider — language model, embeddings, speech-to-text, OCR, storage, cache, email, payments — sits behind an adapter interface with a working local implementation. The whole product runs, end to end, with LLM_DRIVER=local and nothing purchased. Swapping to a hosted provider is an environment variable, not a code change.

The environment, in the parts that matter

QUEUE_DRIVERpostgres
STORAGE_DRIVERlocal  →  s3 in production
CACHE_DRIVERmemory  →  redis in production
AUTH_DRIVERlocal — refused in production
LLM_DRIVER / EMBEDDINGS_DRIVERlocal (deterministic, extractive)
STT_DRIVER / OCR_DRIVERlocal
AI_PROVIDER_NO_TRAININGtrue (cannot be set false)
AI_PROVIDER_RETENTION_DAYS0
EMBEDDINGS_DIM256
UPLOAD_MAX_BYTES524 288 000 (500 MB)
STORAGE_SIGNED_URL_TTL_SECONDS300
SESSION_TTL_SECONDS1 209 600 (14 days)

Configuration is validated by Zod at startup. A missing or malformed value stops the process with a readable message rather than failing later in a request. AUTH_DRIVER=local is explicitly refused when NODE_ENV=production — which means, accurately, that there is currently no production authentication path. That is item 4 on the blocking list.

With Docker instead

docker compose -f infra/docker/docker-compose.yml up adds Redis, MinIO and pgvector. The Compose configuration validates, but it was never executed in the session that produced it, because the Docker daemon was not reachable. Treat the first run as unverified: watch the migrate step.
